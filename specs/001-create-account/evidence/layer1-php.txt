Root cause probe (PHP 8.1.3 FILTER_VALIDATE_EMAIL vs local-part length):

    local= 63 total= 75 filter=ACCEPT
    local= 64 total= 76 filter=ACCEPT
    local= 65 total= 77 filter=REJECT
    local= 66 total= 78 filter=REJECT

FILTER_VALIDATE_EMAIL enforces RFC 5321's 64-octet local-part limit. The corpus
values used 138/139-character local parts, so both boundary emails were rejected
as invalid format while the corpus expected acceptance. This was a fixture defect,
not a validator defect; no requirement or message string was changed.
